## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6) and isolated environment (RUN1, RUN10, ENV6):** the primary path performs no clone, repository install, repository import or worker call, reads no token, and installs nothing into the notebook kernel. Section 2 writes the package, the stage runner, the hash lock compiled from the `pyproject.toml` pins (`uv pip compile pyproject.toml --python-version 3.12 --python-platform x86_64-manylinux_2_28 --generate-hashes --only-binary :all:`), the 4-file snapshot manifest and `NOTICE` into a run directory and verifies each against its SHA-256; a pinned `uv` wheel builds a managed CPython 3.12.12 environment from the lock with `--require-hashes`, reused per lock digest, and every learner cell runs one stage in its own process. `metadata.dimer.generated_from` records the repository, the generating commit, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file differs from the repository, when the lock does not pin every runtime pin with hashes, or when a notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (`tabpfn-v3-classifier-v3_default.ckpt`, `config.json`, `LICENSE`, `README.md`) from the Hugging Face Hub at the immutable revision `24a16a89d245878b846555110985634aa2e656d7` (never `main`; `Prior-Labs/tabpfn_3` is public and not access-gated); `verify_snapshot` re-hashes every entry and additionally requires the checkpoint's digest to equal the module constant `WEIGHTS_SHA256`; `from_pretrained(weights_dir=WEIGHTS_DIR)` binds the verified file as `model_path` for `tabpfn.TabPFNClassifier`.
- **Adaptation:** in-context conditioning only — `fit` registers the training rows as the support set and performs no gradient update; the notebook and the evaluation report (`adaptation`, `adaptation_deviation`) state the proposed RUN7 deviation. Seeds are explicit; `N_ESTIMATORS` is a form field and the optional activity varies it.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/tabpfn_classifier_input_manifest.json` with the schema, the v3 ceilings (`MAX_TRAIN_ROWS` 1,000,000, `MAX_FEATURES` 2,000, `MAX_CLASSES` 160, `MIN_CLASSES` 2, `MIN_ROWS_PER_CLASS` 2), the feature columns, per-split counts, a digest of the training table, warnings as non-fatal findings (a validation/test class absent from `train.csv` is refused as `UNSEEN_CLASSES`) and one recorded rejection from a renamed-target probe; the BYOD table is validated before any split, so input-contract violations stop with their code; `evaluation_report` (EVAL21) writes `outputs/tabpfn_classifier_evaluation_report.json` — `sample-sanity` on the single holdout with the baseline and the reload check; `not-measurable` when no labelled split was scored.
- **Artifact contract and trust boundary:** `save_artifact` writes `model.tabpfn_fit` (fitted state **including the in-context training rows**) + `model.ckpt` (byte copy of the verified checkpoint) + `model.safetensors` (its conversion to safetensors) + `artifact_manifest.json` (task, target, ordered features, per-file SHA-256, base-model identity, and the conversion's provenance: `convertedCheckpointProvenance.derivedFrom` names `model.ckpt` and its SHA-256, plus the converter and its version). This is ARTIFACT_SPEC SER9 (b): `model.ckpt` is a pickle-backed upstream checkpoint kept only so its identity can be verified, and `model.safetensors` is its faithful non-code-executing conversion (SER7). The conversion reads the checkpoint with `torch.load(weights_only=True)`, writes every `state_dict` tensor byte for byte under its own name and every other checkpoint field as canonical JSON in the safetensors header (TabPFN's own `Checkpoint` layout; a field that is not plain data is refused), and `save_artifact` proves it tensor by tensor against `model.ckpt` before the manifest is written (SER8). The bytes are deterministic: the pinned checkpoint always converts to `WEIGHTS_SAFETENSORS_SHA256`. `validate_artifact_bundle` checks schema, member names, sizes, all three digests, the provenance link, the safetensors structure (parsed without torch) and archive safety **before** deserialisation (`verify_conversion=True` adds the tensor-by-tensor comparison; the fresh-process reload uses it), and both the reload and the external-artifact section refuse a bundle whose checkpoint is not the pinned one or whose `model.safetensors` is not its pinned conversion. The estimator is rebuilt from `model.safetensors` (TabPFN reads a `.safetensors` model path with safetensors' `safe_open`), so `model.ckpt` is never unpickled on reload. Digest checks establish internal consistency, not sender authenticity: `model.tabpfn_fit` is serialised Python state (joblib inside a ZIP, SER9 a) and loading it executes trusted model state. The bundle contains training rows — apply the dataset's confidentiality controls to it.
- Classification obligations: the decision rule is `argmax` over uncalibrated class probabilities (no shipped threshold); exported predictions carry one `proba_<class>` column per class in the artifact's class order. The default sample is a deterministic synthetic table drawn in code (`build_synthetic_dataset`); its metrics are plumbing evidence only.
- **BYOD:** one ZIP laid out as `train.csv` (+ optional `val.csv`, `test.csv`) read member by member by `read_dataset_zip` (bare file names only, expanded-size and compression-ratio ceilings; never `extractall`); without `val.csv` a seeded stratified holdout is drawn (independent rows assumed). Gates default to `False` so the sample path never opens an upload dialog; executors supply `BYOD_PATH` / `NEW_DATA_PATH` / `ARTIFACT_ZIP_PATH` / `EXTERNAL_ROWS_PATH` instead. Identifier columns (`DROP_COLUMNS`, default `['record_id', 'category']`; in Section 10 `record_id` and `category` when present) are kept beside the predictions and never given to the model.
- `tools/validate_release_assets.py` performs source validation only (`scripts/validate_colab_tutorial.py` delegates to it). It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`. `scripts/execute_notebook_release.py` is the previous (worker-driven) notebook's bootstrap-stripping harness and does not apply to the standalone notebooks (they have no bootstrap region); run them directly with a kernel executor.
