## Conformance notes

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, repository import, worker call or subprocess, and reads no token. Section 2 is `src/tabpfn_classifier_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 4-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins (`torch==2.11.0`, `tabpfn==8.1.0`, `pandas==2.3.2`, `scikit-learn==1.9.0`, `huggingface-hub==0.36.2`). `metadata.dimer.generated_from` records the repository, the module's last commit, its SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py`, `tests/test_companion_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when a notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (`tabpfn-v3-classifier-v3_default.ckpt`, `config.json`, `LICENSE`, `README.md`) from the Hugging Face Hub at the immutable revision `24a16a89d245878b846555110985634aa2e656d7` (never `main`; `Prior-Labs/tabpfn_3` is public and not access-gated); `verify_snapshot` re-hashes every entry and additionally requires the checkpoint's digest to equal the module constant `WEIGHTS_SHA256`; `from_pretrained(weights_dir=WEIGHTS_DIR)` binds the verified file as `model_path` for `tabpfn.TabPFNClassifier`.
- **Adaptation:** in-context conditioning only — `fit` registers the training rows as the support set and performs no gradient update; the notebook and the evaluation report (`adaptation`) both state that the private-worker fine-tune path is not carried. Seeds are explicit (`SAMPLE_SEED`, `SEED`); `N_ESTIMATORS` is a form field.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/tabpfn_classifier_input_manifest.json` with the schema, the v3 ceilings (`MAX_TRAIN_ROWS` 1,000,000, `MAX_FEATURES` 2,000, `MAX_CLASSES` 160, `MIN_CLASSES` 2, `MIN_ROWS_PER_CLASS` 2), the feature columns, per-split counts, a digest of the training table, warnings as non-fatal findings and one recorded rejection from a renamed-target probe; `evaluation_report` (EVAL21) writes `outputs/tabpfn_classifier_evaluation_report.json` — `sample-sanity` on the single holdout with the baseline and the reload check; `not-measurable` when no labelled split was scored (always the case in the companion).
- **Artifact contract and trust boundary:** `save_artifact` writes `model.tabpfn_fit` (fitted state **including the in-context training rows**) + `model.ckpt` (byte copy of the verified checkpoint) + `artifact_manifest.json` (task, target, ordered features, per-file SHA-256, base-model identity); `validate_artifact_bundle` checks schema, member names, sizes, digests and archive safety **before** deserialisation, and both notebooks refuse a bundle whose checkpoint is not the pinned one. Digest checks establish internal consistency, not sender authenticity: `model.tabpfn_fit` / `model.ckpt` are serialised Python/torch state and loading them executes trusted model state. The bundle contains training rows — apply the dataset's confidentiality controls to it.
- Classification obligations: the decision rule is `argmax` over uncalibrated class probabilities (no shipped threshold); exported predictions carry one `proba_<class>` column per class in the artifact's class order. The default sample is a deterministic synthetic table drawn in code (`build_synthetic_dataset`); its metrics are plumbing evidence only.
- **BYOD:** one ZIP laid out as `train.csv` (+ optional `val.csv`, `test.csv`) read member by member by `read_dataset_zip` (bare file names only, expanded-size and compression-ratio ceilings; never `extractall`); without `val.csv` a seeded stratified holdout is drawn (independent rows assumed). Gates default to `False` so the sample path never opens an upload dialog; executors supply `BYOD_ZIP_PATH` / `NEW_DATA_PATH` / `ARTIFACT_ZIP_PATH` instead.
- `tools/validate_release_assets.py` performs source validation only (`scripts/validate_colab_tutorial.py` delegates to it). It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`. `scripts/execute_notebook_release.py` is the previous pair's bootstrap-stripping harness and does not apply to the standalone notebooks (they have no bootstrap region); run them directly with a kernel executor.
